# fal media migration

Approved scope: replace account-browser image/video generation with fal API, then retire the Gemini creation bridge only after successful live image/video/archive verification. Text chat, existing conversations, local-delete/archive retention, and front-end layout stay unchanged. No billable tests or credit purchases authorized yet.

Architecture: Next server routes submit to fal's durable queue. Store provider request metadata in the existing archive turn; never resubmit an ambiguous submission. Authenticated webhooks fetch the result and copy original bytes into private Supabase storage, with polling/cron recovery. Old account media remain readable. Gate new submissions with FAL_MEDIA_ENABLED, default off. Reuse built-in fetch and Node crypto; no new runtime dependencies or persistent browser required for fal.

Chosen economical defaults (implementation choice): fal-ai/flux-2/klein/4b, its /edit endpoint, minimax/h3-max-turbo/text-to-video and /image-to-video. Image count 1, 1024x1024, video 5 seconds/768P. Keep provider safety checks on. Endpoint schemas verified 2026-11-11. Queue URLs must use queue.fal.run; output downloads allow fal.media only, no credentials or redirects. API credentials remain server-side. Use signed fal webhook verification with pinned JWKS origin and request-ID binding.
