# צ׳אט AI

אתר צ׳אט AI קליל בעברית, שמותאם לטלפון. האתר מדבר רק עם הדומיין של עצמו (בלי CDN, בלי גופנים חיצוניים ובלי אנליטיקס), כך שהוא עובד גם בטלפון עם סינון תוכן.
הכניסה מוגנת בקוד גישה. התשובות מגיעות מכל ספק שתומך בממשק תואם OpenAI (ברירת המחדל: NVIDIA, אפשר גם Gemini ואחרים).
השיחות נשמרות בדפדפן (localStorage): רשימת שיחות עם שינוי שם, נעיצה ומחיקה.

## מה צריך

- Node.js בגרסה 20.9 ומעלה
- מפתח API של ספק AI, למשל NVIDIA (מ-build.nvidia.com, לוחצים על "Get API Key")

## הרצה מקומית

1. מתקינים את התלויות:
   ```bash
   npm install
   ```
2. מעתיקים את `.env.example` לקובץ חדש בשם `.env.local` וממלאים את הערכים (פירוט בטבלה למטה).
3. בודקים אילו מודלים זמינים למפתח שלכם, ובוחרים אחד ל-`AI_MODEL`:
   ```bash
   npm run models
   ```
4. מריצים:
   ```bash
   npm run dev
   ```
   ופותחים את http://localhost:3000 בדפדפן.

## משתני סביבה

| משתנה | חובה | מה זה |
| --- | --- | --- |
| `AI_API_KEY` | כן | מפתח ה-API של הספק |
| `AI_MODEL` | כן | מזהה המודל. הרשימה המלאה: `npm run models` |
| `AI_BASE_URL` | לא | כתובת הממשק התואם OpenAI. ברירת מחדל: `https://integrate.api.nvidia.com/v1` |
| `AI_REASONING_EFFORT` | לא | כמה המודל "חושב" לפני שהוא עונה: `none` / `low` / `medium` / `high`. ברירת מחדל: `none` (התשובה מתחילה הכי מהר). יותר חשיבה = התשובה מתחילה מאוחר יותר. אם הספק דוחה את הפרמטר, מגדירים ערך ריק |
| `AI_MODELS` | לא | רשימת אפשרויות שהמשתמש בוחר מהן בכפתור שליד כפתור השליחה, לכל שיחה בנפרד (פירוט למטה). בלי המשתנה: אפשרות אחת לפי `AI_MODEL`, בלי בורר ובלי העלאת תמונות |
| `ACCESS_CODE` | מומלץ | הקוד שמקלידים במסך הכניסה. כדאי לבחור קוד ארוך שקשה לנחש. שינוי הקוד מנתק את כל מי שמחובר. **בלי קוד (ריק או לא מוגדר) האתר פתוח לכל מי שיש לו את הכתובת** |

### בורר מודלים (`AI_MODELS`)

כל אפשרות היא שורה בפורמט `מפתח|מזהה מודל|שם בעברית|תיאור קצר|רמת חשיבה|תמונות`, ואפשרויות מופרדות בפסיק:

- **מפתח:** מזהה קצר באנגלית (אותיות, ספרות, `-`, `_`). חייב להיות ייחודי.
- **רמת חשיבה:** `none` / `low` / `medium` / `high`, או ריק כדי להשתמש ב-`AI_REASONING_EFFORT`. `off` = לא לשלוח את הפרמטר בכלל, למודלים שדוחים אותו (למשל Gemini Flash-Lite).
- **תמונות:** `1` אם המודל מקבל תמונות, `0` אם לא. כשהאפשרות לא תומכת בתמונות, כפתור הצירוף מוסתר.
- האפשרות הראשונה היא ברירת המחדל. אותו מודל יכול להופיע כמה פעמים עם רמות חשיבה שונות.
- מותר פסיק בתוך התיאור. שורה פגומה מדולגת (עם אזהרה בלוג של השרת).
- ברשימה מוצג גם שם קריא של המודל, שנגזר אוטומטית מהמזהה (`gemini-3.6-flash` ← `Gemini 3.6 Flash`), וגם מתחת לכל תשובה (למשל `מהיר · Gemini 3.6 Flash`).
- הדפדפן מקבל רק את המפתח, השם, התיאור, השם הקריא של המודל, האם יש תמונות, וקבוצת המכסה (שהיא מפתח של אחת האפשרויות). השרת מקבל מהדפדפן רק מפתח של אפשרות מהרשימה. מזהה המודל, המפתח והכתובת נשארים בשרת, והשרת משתמש רק באפשרויות מהרשימה.

```bash
AI_MODELS=fast|gemini-3.6-flash|מהיר|לרוב השאלות|none|1,deep|gemini-3.6-flash|מעמיק|לשאלות מורכבות, איטי יותר|medium|1,alt|gemini-3.1-flash-lite|חלופה|עברית טובה, מתחיל לענות לאט יותר|off|1,lite|gemini-3.5-flash-lite|גיבוי|הכי מהיר, עברית פחות מדויקת|off|1
```

**מכסה יומית:** בחשבון החינמי של Gemini יש מגבלת בקשות ליום **לכל מודל בנפרד** (למשל 20 בקשות ביום ל-`gemini-3.6-flash`). המכסה מתחדשת בחצות לפי שעון החוף המערבי בארה"ב. אפשרויות שמשתמשות באותו מודל ("מהיר" ו"מעמיק") חולקות את אותה מכסה. "חלופה" ו"גיבוי" הן מודלים אחרים, וכל אחד עם מכסה משלו.

כשהמכסה היומית של מודל נגמרת:

- ליד כל האפשרויות של אותו מודל ברשימה מופיע הסימון "נגמרה המכסה · מתחדש בעוד X שעות" (או "מחר"). הן נשארות זמינות לבחירה, וההחלטה בידי המשתמש.
- כפתור הבורר שליד כפתור השליחה מקבל נקודה כתומה, ומהבהב לרגע כשזה קורה באמצע שיחה.
- הודעת השגיאה מפנה לבורר. האתר **לא** מחליף אפשרות לבד.
- הסימון נשמר בדפדפן ונעלם לבד כשהמכסה מתחדשת. חסימה לדקה (מגבלה לדקה) לא מסמנת כלום, ההודעה פשוט מבקשת לחכות דקה.

כדי לקבל מכסה גדולה יותר צריך להפעיל חיוב בחשבון Google AI Studio.

### תמונות

כשהאפשרות הנוכחית תומכת בתמונות (`1` ב-`AI_MODELS`), מופיע כפתור צירוף בצד ימין של שורת ההקלדה:

- עד 3 תמונות בהודעה (JPEG, PNG, WebP, ו-HEIC אם הדפדפן יודע לפתוח אותו). אפשר לשלוח תמונה בלי טקסט.
- הדפדפן מקטין כל תמונה לעד 1600 פיקסלים בצד הארוך ושומר אותה כ-JPEG, כך שכל תמונה קטנה מ-1MB. כיוון הצילום (EXIF) נשמר.
- בהיסטוריה נשמרת רק תמונה ממוזערת (כ-200 פיקסלים), כדי לא למלא את האחסון של הדפדפן.
- למודל נשלחות רק התמונות של ההודעה האחרונה שיש בה תמונות. תמונות מהודעות קודמות מוחלפות בטקסט `[תמונה שנשלחה קודם]`, כדי לחסוך בטוקנים.
- השרת בודק סוג, כמות וגודל, ודוחה בקשה גדולה מ-4MB.

השמות הישנים (`NVIDIA_API_KEY`, `NVIDIA_MODEL`, `NVIDIA_BASE_URL`) עדיין עובדים: אם משתנה חדש חסר, האתר משתמש בשם הישן.

### דוגמאות לספקים

NVIDIA (ברירת המחדל, אפשר להשמיט את `AI_BASE_URL`):

```bash
AI_API_KEY=nvapi-...
AI_MODEL=meta/llama-3.3-70b-instruct
```

Gemini (דרך הממשק התואם OpenAI של Google):

```bash
AI_API_KEY=...            # מפתח מ-Google AI Studio
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
AI_MODEL=gemini-3.6-flash # או כל מודל אחר מ-npm run models
```

מודלים שמציגים "חשיבה" בתגיות `<think>…</think>` נתמכים: החלק הזה מסונן ולא מוצג.

### קישור כניסה ישיר

אפשר לשלוח לחבר קישור שמכניס אותו בלי להקליד קוד:

```
https://<כתובת האתר>/?k=<ACCESS_CODE>
```

הקישור מכניס, מוחק את הקוד משורת הכתובת, ומשאיר את החבר מחובר ל-365 יום (כמו כניסה רגילה). קוד שגוי בקישור מוביל למסך הכניסה עם הודעת שגיאה, אחרי השהיה של שנייה. כדאי לשלוח את הקישור רק בערוץ פרטי: מי שמחזיק אותו נכנס, והקוד עשוי להופיע בלוג הבקשות של Vercel.

## יצירת תמונות וסרטונים (OpenArt)

האתר יכול ליצור תמונות וסרטונים דרך חשבון ה-OpenArt של הבעלים, בעזרת שרת ה-MCP של OpenArt. החשבון מחובר פעם אחת דרך דף ניהול, והשרת ממשיך לעבוד לבד מאותו רגע.

| משתנה | מה זה |
| --- | --- |
| `KV_REST_API_URL` + `KV_REST_API_TOKEN` (או `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`) | Upstash Redis. נוצר אוטומטית כשמוסיפים Upstash מה-Marketplace של Vercel |
| `OPENART_TOKEN_KEY` | מפתח הצפנה לאסימונים (32 בתים ב-base64). ליצירה: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` |
| `ADMIN_CODE` | קוד לדף הניהול `/admin/openart`. לבעלים בלבד, שונה מ-`ACCESS_CODE` |
| `CRON_SECRET` | סוד למשימת הרענון היומית. Vercel שולח אותו אוטומטית למשימות Cron |
| `OPENART_DAILY_CREDIT_CAP` | תקרת קרדיטים ליום (לפי שעון ישראל). ברירת מחדל: 200 |
| `OPENART_IMAGE_MODELS` / `OPENART_VIDEO_MODELS` | לא חובה. אפשרויות התמונה והסרטון, בפורמט `מפתח|מזהה מודל|שם|תיאור|הגדרות` (הגדרות כמו `duration=5;resolution=540p`). ברירת מחדל: Nano Banana 2 Lite, Nano Banana 2 (1K), PixVerse V6 (5 שניות, 540p), Veo 3.1 (4 שניות, 720p) |

- **דף הניהול `/admin/openart`:** מצב החיבור, יתרת הקרדיטים, "חיבור / חיבור מחדש" (מעבר ל-OpenArt לאישור) ו"ניתוק" (ביטול האסימונים ומחיקתם).
- **אסימונים:** נשמרים מוצפנים (AES-GCM) ב-Redis. אסימון הרענון מתחלף בכל רענון, ולכן נשמר תמיד החדש ביותר. נעילה ב-Redis מבטיחה ששני רענונים לא ירוצו במקביל.
- **רענון יומי:** משימת Cron (`vercel.json`) מרעננת פעם ביום, כדי שהחיבור לא יפוג.
- **לפני כל יצירה:** השרת מחשב את המחיר המדויק (`model_cost`), והמשתמש מאשר אותו. אם המחיר השתנה בינתיים, הבקשה נדחית עם המחיר החדש. התקרה היומית נבדקת ונרשמת לפני שהיצירה מתחילה, ויצירה שנכשלה מחזירה את הקרדיטים לתקרה.
- **התוצאות** מוגשות מהדומיין של האתר (`/media/...`, כולל דילוג בתוך סרטון והורדה). הדפדפן אף פעם לא פונה ל-`cdn.openart.ai`.
- **אם החיבור נשבר:** דף הניהול מראה "החיבור נשבר" ומאפשר לחבר מחדש. הצ׳אט ממשיך לעבוד כרגיל.

## העלאה ל-Vercel

1. מעלים את הפרויקט ל-GitHub ומייבאים אותו ב-Vercel (ההגדרות של Next.js מזוהות לבד).
2. ב-**Settings ← Environment Variables** מוסיפים את המשתנים מהטבלה (`AI_API_KEY`, `AI_MODEL`, `ACCESS_CODE`, ולפי הצורך `AI_BASE_URL` ו-`AI_MODELS`) עבור Production.
3. מבצעים Deploy. אם שיניתם משתנה אחרי ה-Deploy, צריך לבצע Redeploy כדי שהשינוי ייכנס לתוקף.

## בדיקות

```bash
npm test            # בדיקות יחידה: קוד גישה, קיצור היסטוריה, אחסון שיחות, סינון <think>, בורר מודלים, בדיקת תמונות, מכסה יומית
npm run typecheck   # בדיקת TypeScript
npm run lint
npm run build
```

בדיקות דפדפן (Playwright) רצות מול שרת AI מדומה, כך שלא צריך מפתח אמיתי. האפליקציה לבדיקות עולה בפורט 3101 עם שלוש אפשרויות מודל לדוגמה (ההגדרות ב-`tests/start-test-app.mjs`):

```bash
npm run build
npm run mock:nvidia      # בחלון נפרד
npm run test:app         # בחלון נפרד
npm run e2e          # צ׳אט ו-RTL
npm run e2e:history  # רשימת השיחות
npm run e2e:models   # בורר המודלים (כפתור ליד השליחה)
npm run e2e:images   # צירוף תמונות
npm run e2e:quota    # סימון מכסה יומית בבורר
npm run e2e:auth     # קישור כניסה ישיר, עוגייה, אתר פתוח
```

`e2e:models` ו-`e2e:auth` צריכים גם מופע שני, עם אפשרות מודל אחת ובלי קוד גישה:

```bash
TEST_ACCESS_CODE= TEST_AI_MODELS='only|mock-fast|only||none|1' PORT=3102 npm run test:app   # בחלון נפרד
```

צילומי המסך נשמרים בתיקייה `test-screenshots/`. אם הדפדפן של Playwright לא מותקן, מריצים `npx playwright install chromium`, או מגדירים `CHROME_PATH` לנתיב של Chromium קיים.

## מבנה

- `app/page.tsx` + `components/Chat.tsx`: מסך הצ׳אט
- `components/Sidebar.tsx`: רשימת השיחות (מגירה בטלפון, סרגל צד במחשב)
- `lib/history.ts`: שמירת השיחות ב-localStorage, העברה מהגרסה הקודמת, מיון וקיבוץ לפי תאריך
- `components/Markdown.tsx`: הצגת תשובות (נטען רק כשיש תשובה ראשונה)
- `app/login/page.tsx` + `app/api/login/route.ts`: מסך הכניסה
- `app/api/chat/route.ts`: ה-API ששולח את השיחה לספק ה-AI ומזרים את התשובה
- `proxy.ts`: חוסם גישה לצ׳אט ול-API בלי עוגיית כניסה תקפה
- `lib/systemPrompt.ts`: ההנחיות למודל (תמיד לענות בעברית, בקצרה, בלי קישורים)
